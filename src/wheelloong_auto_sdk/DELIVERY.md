# SDK 开发与交付边界

当前仓库保持纯 Python 源码开发模式。此阶段不生成 Wheel、不运行 Cython，
也不删除或替换任何 Python 源文件。

## 平台策略

- 主发布平台：`aarch64`、Ubuntu 22.04、Python 3.10、ROS 2 Humble。
- 兼容平台：`x86_64`，公共 API、默认值、异常和测试必须保持一致。
- 源码不得按 CPU 架构分叉；最终二进制产物按架构分别构建。
- 当前远端开发机已确认为 `aarch64` 和 Python 3.10.12。

## 当前改造约束

- 任务程序只能依赖 `wheelloong_auto_sdk` 顶层公共 API。
- ROS 消息、Service 和 Action 类型继续限制在 Backend 内部。
- 运行时代码不得写死开发者用户名、工作空间或 Home 目录。
- 用户数据通过参数或环境变量选择，不作为 SDK 源码的一部分。
- `.vscode`、`test`、构建目录和开发日志属于开发资产。
- 所有样例均由包内 `console_scripts` 安装，并统一使用
  `ros2 run wheelloong_auto_sdk <可执行名>` 启动。

## 最终交付原则

正式发布时才增加受保护构建流程，并分别生成 `aarch64` 和 `x86_64`
产物。交付内容包括二进制 SDK、类型声明、API 文档和示例；不交付
Backend 源码、测试、VS Code 配置、构建目录或版本库元数据。

发布前仍需完成：Cython 构建配置、类型声明、双架构流水线、版本兼容
检查、安装脚本、许可证、校验和以及真实机器人验收。当前阶段不执行这些步骤。
